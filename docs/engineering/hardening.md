# 公共组件可靠性加固

按顺序独立提交，每阶段通过对应验证后再继续：

1. 参数契约：非法参数返回 2；在任何写入和加锁前校验；执行器保留命令退出码。
2. 分发可靠性：规范化真实路径、目标互斥、锁内复核、故障恢复；生成失败不留下伪完整项目。
3. 平台验证：统一回归入口与环境证据；最低系统/架构矩阵；真实安装独立记录。
4. 接口治理：公开 API 清单、私有命名、输出/加载契约、兼容升级测试。
5. 发布管理：独立版本、变更记录、来源清单校验与离线发布验收。

第一阶段增加 `validation.sh` 纯校验函数和 `tests/arguments.sh`。参数测试覆盖直接调用、条件调用和 OR 调用；通过命令/锁探针及空沙箱断言验证非法输入无副作用。固定 vendor 暂保留原版本，后续通过同步工具显式升级，禁止直接修改快照。

验证命令仍以 [开发指南](../guides/development.md) 为唯一来源。平台环境不可用时记录为待验证，不把 CI 配置当作实机通过。不会在本机运行安装、sudo、USB 制作，也不推送或发布。

第二阶段：工具共享可信的 `tools/lib/artifact_runtime.sh`，对规范化目标使用持久 fcntl 锁；固定事务目录允许下一次同步恢复 SIGKILL 留下的备份。目标异常时保留备份。生成器在同文件系统完成候选项目后一次 rename 发布；生成项目携带工具辅助模块。新增故障注入测试覆盖 TERM、KILL、恢复受阻、路径别名和并发等待。

第三阶段：统一 `tests/run_all.sh` 生成不可覆盖的环境/退出码/日志报告，CI 与发布门禁共用；新增可声明预期 OS 和架构的手动兼容矩阵。当前只能实测本机 arm64，macOS 14、Intel 与真实安装明确保留待验证状态，见 [平台验证](platform-validation.md)。

第四阶段：API.txt 管理公开函数；私有实现统一 `_sk_`，应用适配层只转发公开接口。新增经过校验的候选文件提交接口；SSH 在读取配置前获取资源锁。日志保留默认 merged 兼容模式，模板显式启用 separate 保持 stdout/stderr 分离。冻结消费者分别对旧快照和新源运行，比较实际配置/退出码；另验证重复加载、清单漂移和分离通道。

第五阶段：新增静态发布检查与离线目录产物构建，要求干净、已跟踪的组件源码，校验 API/变更记录/版本及 manifest 头；源变化、ignored 未跟踪文件和已有产物被拒绝。实际示例显式升级到 0.2.0，原 0.1.0 快照保留为不可修改的兼容测试基线。未推送或发布。
