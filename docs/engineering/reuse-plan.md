# 公共组件与项目模板实施约定

目标：让当前项目作为公共库的真实使用方，同时提供可离线复制、独立运行的 macOS Shell 项目模板。支持 macOS 14+ 的系统 `/bin/zsh` 和 BSD 工具；不承诺 Bash/Linux 兼容。

按以下顺序实施，每步验证后独立提交：

| 阶段 | 交付与验收 |
| --- | --- |
| 1 边界 | 本文确定接口、依赖、兼容及迁移规则 |
| 2 抽离 | `packages/zsh-kit` 独立组件；现有 `lib` 适配；应用完整回归 |
| 3 分发 | 独立契约测试、固定版本离线 vendor、哈希检查及显式升级 |
| 4 模板 | 集中元数据、生成器、最小 CLI、测试及 CI；带空格路径生成验证 |
| 5 示例 | 文件整理示例、重复执行与失败恢复、兼容升级演练 |

依赖方向：`bin/setup/maintain → lib（应用适配）→ packages/zsh-kit/lib`。新项目通过 `vendor/zsh-kit` 使用同一组件；公共库禁止反向引用业务目录。

| 原组件 | 公共机制 | 应用保留策略 |
| --- | --- | --- |
| colors | 日志等级、计时 | 现有 UI 与兼容函数 |
| command_runtime/workflow | 命令预览、执行、阶段错误传播 | DRY_RUN 默认值、安装恢复提示 |
| resource_lock | 真实路径锁、释放与重入 | Homebrew prefix 的资源标识 |
| config_writer | 原子替换、标记块、INI 批次 | `.zshrc` 位置、管理者标识 |
| logging | 字节轮转、保留、捕获与排空 | 日志位置、环境变量命名 |

公共函数使用 `sk_`，内部函数使用 `_sk_`，状态使用 `SK_`。旧函数在应用层转发；私有实现不属于兼容承诺。加载模块只定义函数及 namespaced 状态，不访问网络、创建文件、改变调用方选项或安装 trap；重复加载不能清空运行状态。显式执行函数才允许建立资源和退出钩子。

数据写 stdout，诊断写 stderr。参数按位置传递并完整引用；非法参数返回 2，操作失败返回非零，执行器和阶段编排保留被调用动作的退出码。动作即使在 `if`/`||` 中执行，也必须显式检查关键命令，不能只依赖 errexit。

日志策略通过 `SK_LOG_*` 配置，目录由调用方传入。捕获必须成对开始/结束，结束保留业务退出码。配置写入在同目录构建候选文件并替换；相同内容不重写，失败保留原文件。多文件业务事务仍由应用层负责；不宣称保留扩展属性/ACL 或提供跨文件原子性。

锁协议继续使用 `/tmp/macos-scripts-locks-$EUID`（协议兼容名称，并非项目目录配置），对规范化资源路径取 SHA-256，fcntl 锁文件不删除；新旧项目共享同一协议。允许同步调用链重入，不允许在持锁事务内并行派生写入任务。获取顺序：业务运行锁、Homebrew 实例、配置文件。

vendor 必须携带版本、许可证、源 revision 与逐文件摘要。运行时不下载或更新；升级必须显式同步、审阅差异并执行调用方测试。0.x 次版本变化需要审阅接口，补丁升级保持现有公开契约。

验证以 [开发指南](../guides/development.md) 为唯一命令来源。核心测试必须在复制出的独立包运行；模板测试必须使用临时 HOME、带空格路径和替换后的项目名。不得在验证中安装软件、修改真实用户配置或整理用户文件。

风险控制：保留应用适配层和独立 Bootstrap 的生成校验；每阶段一个提交，可单独回退。模板不默认包含 Homebrew、发布或远程 Bootstrap，后续按项目需要接入。
