# 边界可靠性与维护职责收敛

目标：修复配置边界行为，将发布能力移出用户 CLI，补齐强制中断恢复和认证验证。

按阶段验证、独立提交：

1. 配置写入：INI 与管理标记按原文传递给 awk；SSH 候选文件位于解析后的目标目录。覆盖反斜杠、Unicode、空值及跨目录链接。
2. 发布：内部工具与 workflow 承担版本校验、安装验收和发布。
3. Homebrew：持久化事务与安全恢复。
4. SSH：区分配置与认证结果，明确主机信任策略。
5. 验收：边界覆盖和真实平台证据。
6. 模块：规范导入路径和失败契约。

风险：恢复不能覆盖用户后续修改；发布迁移必须同步安装包、测试与文档。真实安装和 USB 验收仅在可恢复的专用环境进行，未执行的项目明确记录。

验证命令以 [开发指南](../guides/development.md) 为准。每阶段完成后在此补充结果。

阶段 1 已完成；完整沙箱回归通过（报告 `/private/tmp/scripts-stage1b-20261029`）。组件源修复不直接修改冻结 vendor，消费者通过显式升级获取新版本。

阶段 2 已完成；发布能力移入 `tools/release/`，公共 CLI/安装包不包含发布模块。版本缺失或不一致拒绝验收；workflow 明确 tag、源码身份、Formula URL 和实际安装版本，通过后才进入发布 job。完整沙箱回归通过（`/private/tmp/scripts-stage2b-20261029`）；本次未触发远端发布或真实安装。

阶段 3：Homebrew 备份增加 active/rolled-back/committed 状态、作用域、原始摘要和步骤完成后的检查点。下次启动先验证所有目标、备份完整性及当前内容，再恢复中断事务；成功提交删除备份，失败恢复保留备份。写入与检查点之间被 KILL 时无法证明文件归属，保守拒绝自动覆盖；提示核对备份并人工恢复后将 state 标记 rolled-back。没有承诺断电时文件系统缓存的持久性；不将进程信号测试当作真实断电验收。

阶段 3 完整沙箱回归通过：`/private/tmp/scripts-stage3-20261029`，包括新 SIGKILL 恢复测试和原有真实临时 Git 配置回滚测试。

阶段 4：SSH 单独报告本地配置完成与远端认证；正常会话退出 0 以及退出 1 的 GitHub/GitLab 标准成功响应视为已确认。其他失败保留原码，255 不会被成功文案覆盖。BatchMode 与 StrictHostKeyChecking=yes 防止隐式密码交互和自动信任；首次连接需用户通过可信渠道核对指纹后手动确认。公钥上传或认证失败保留本地配置，可重试。

阶段 4 完整沙箱回归通过：`/private/tmp/scripts-stage4-20261029`。认证响应与参数通过命令桩验证，没有连接真实 Git 服务或改动用户 known_hosts。
