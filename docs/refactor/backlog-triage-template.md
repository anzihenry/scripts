# Backlog Triage Template

## 目标

把后续需求、重构项、修复项统一映射到本项目的 4 个北极星目标上，再决定优先级与验收方式，避免 backlog 退化成“想到什么做什么”。

## 四个目标

### 1. 环境管理

适用范围：

- `setup/`
- `setup/lib/`
- `setup/brew.conf.sh`
- `maintain/` 中与系统环境维护直接相关的脚本
- `lib/colors.sh`
- `lib/utils.sh`

用于判断的问题：

- 这项工作是不是在增强 macOS 初始化、配置或维护主路径？
- 它是否提高了幂等性、安全性或重复执行稳定性？

### 2. 定时任务

适用范围：

- `job/`
- `job/lib/`

用于判断的问题：

- 这项工作是不是在增强 `launchd` 任务的创建、启停、状态查看、删除或 dry-run 能力？
- 它是否提升了任务日志、参数透传或任务文件生成的稳定性？

### 3. 统一 CLI

适用范围：

- `bin/macos-scripts`
- `bin/lib/`

用于判断的问题：

- 这项工作是不是在强化统一入口，而不是让用户回到底层脚本？
- 它是否提升了帮助文案、参数校验或子命令一致性？

### 4. 自验证 / 自测试

适用范围：

- `tests/`
- `lint/lint_shell.sh`
- `docs/refactor/`
- `README.md`
- `AGENTS.md`
- `.github/instructions/*.instructions.md`

用于判断的问题：

- 这项工作是不是在提高“改完之后能证明没坏”的能力？
- 它是否新增或强化了语法检查、smoke、lint、验证文档或协作说明？

## 优先级规则

### P0：主路径断裂 / 明显风险

满足任一条，优先最高：

- 统一 CLI 无法完成主功能
- setup / job 主路径行为错误
- dry-run、参数校验、日志保护机制失效
- 现有测试已经发现真实回归
- 文档承诺与真实行为明显不一致

### P1：高价值结构收敛

适合优先推进：

- 能把大脚本拆成稳定模块
- 能统一重复出现的高风险逻辑
- 能降低后续修改成本
- 能让某个入口变成真正的编排层

### P2：测试护栏增强

适合持续补强：

- 新增主路径 smoke
- 给高风险失败路径补测试
- 给常改模块补语法/验证入口
- 让文档中的验证命令真正可执行

### P3：体验与一致性优化

放在主路径稳定后：

- 文案更清晰
- 命名更一致
- 示例更完整
- 输出格式更统一

### P4：局部美化 / 低收益整理

最后处理：

- 纯格式移动
- 低收益命名调整
- 不增强主路径或验证能力的局部整理

## Triage 模板

每个 backlog 项建议统一使用下面结构：

```md
### <任务标题>

- 目标：环境管理 / 定时任务 / 统一 CLI / 自验证
- 优先级：P0 / P1 / P2 / P3 / P4
- 类型：功能修复 / 结构重构 / 测试护栏 / 文档对齐

- 背景：
  用一句话说明为什么现在要做这件事。

- 影响模块：
  列出会改到的文件或目录。

- 判断依据：
  - 它解决的主问题是什么？
  - 它为什么属于这个目标？
  - 它为什么应该排在这个优先级？

- 一次提交做什么：
  把本项拆成一个可 review 的最小提交目标。

- 验收：
  写清楚改完要跑什么命令，至少包含一条可复现验证。
```

## 快速判断流程

收到一个新任务时，按顺序回答：

1. 它服务哪个目标？
2. 它是不是主路径问题？
3. 它是不是在降低后续维护成本？
4. 它能不能顺手补一个明确验证？

判断建议：

- “主路径 + 可验证” -> 往前排
- “结构收敛 + 低风险” -> 往前排
- “只是更整齐” -> 往后排

## 当前默认排序倾向

基于当前仓库状态，默认按这个顺序排：

1. 先保主路径
   - setup 主链路
   - job 主链路
   - CLI 主入口一致性
2. 再补测试护栏
   - smoke 扩面
   - 失败路径护栏
   - 验证入口对齐
3. 再做剩余结构收敛
   - `maintain/` 大脚本
   - 剩余高风险配置写入
   - 重复 helper 统一
4. 最后做体验打磨
   - 文案
   - 示例
   - 轻量目录整理

## 使用建议

- 新任务进入 backlog 前，先用本模板归档，不直接开做。
- 若一个任务无法明确落到 4 个目标之一，默认优先级下调。
- 若一个任务没有明确验收命令，默认不能进入“立即执行”状态。
